## 3. Preservation and correction protocol

1. Do not modify, rename, delete or replace original raw captures, logs, CSVs, graphs or source scripts.
2. Before any processing, record repository commit, file path, file size and SHA-256 for each source artifact.
3. Store each corrected script under a separate versioned name (for example, `run_test-2.audit-v1.py`); retain the original path unchanged.
4. Store derived files in a new output directory that identifies the script version and processing date. Do not write into historical `data/` or `result/` directories.
5. For every correction, document the original behavior, reason for correction, exact change, test performed, environment and output hashes.
6. A corrected/reprocessed result is a new result. It must not be represented as the historical published result unless provenance proves they are the same execution.
7. Close a pending item only when the evidence, correction and verification are recorded. If evidence is unavailable, retain the item as unresolved.
